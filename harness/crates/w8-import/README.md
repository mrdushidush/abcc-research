# `w8-import` — ABCC's 100-task suite → a `corpus/SPEC.md` v1 corpus

Step 2 of the W8 plan. Extract → rewrite → emit, with gate point 1 measured at import time on
all 90 tasks against the **rewritten** verifier.

```bash
cargo run -p w8-import -- --out ../corpus              # emit; never overwrites authored tasks
cargo run -p w8-import -- --out /tmp/x --only tm_utils # one task, somewhere else, to diff
cargo test -p w8-import                                # 34 unit tests
```

Zero third-party dependencies. It parses one JavaScript file, writes TOML whose comment layout
it has to control anyway, and shells out to `bash`.

## What it does

| Stage | File | Notes |
|---|---|---|
| extract | `donor.rs` | JS string walker + `js_unescape`; `BUGGY_FILES`; the stable 90 (F11) |
| rewrite | `rewrite.rs` | prompts, verifier bodies, dispositions, dependency closure |
| verify.sh | `verify_sh.rs` | SPEC §8's contract, two templates |
| gate | `gate.rs` | interpreter probing, the tiers, the verdict vocabulary |
| emit | `emit.rs` | the corpus tree, provenance partition, disposition |

Output on the current donor (`d5528ea`): **54 clean · 24 presence-only · 12
quarantined-with-baseline**, aggregate denominator 78.

## The two things that make the numbers mean anything

**The gate is one-sided.** Every tier expects FAIL, so a `verify.sh` that could never print PASS
would report 80 sound verifiers and look like a flawless run. The importer therefore runs a
**positive control** first: 50 of the 90 donor prompts dictate the artifact body verbatim, which
is a reference solution by construction. 49 of 50 pass. If none passed, the import aborts rather
than writing gate results.

**The rewritten verifier is the authoritative one.** A gate result measured against the donor's
verifier does not describe the verifier this corpus runs. On the one task where both exist —
`fix_sql_inject`, hand-authored as the worked example — the generated and hand-written scripts
were run against all five tiers and **agree on every verdict**, including the F8 case where the
sham PASSes. The emitted `prompt.txt` and `fixture/` are byte-identical to the hand-authored
ones.

## Five things the building surfaced that reading would not have

All measured, all recorded in `corpus/suites/u100/suite.toml`'s caveats.

1. **The donor source is entirely CRLF** — 3,521 `\r\n`, zero bare `\n`. Everything anchored on
   `\n` silently missed. This emptied two reconstructed dependency fixtures, and their gate
   point 1 then read `sound` while the verifier crashed on the missing module before testing
   anything. The tell was that the error class did not change between the `absent` and `stub`
   tiers; after the fix, `absent` reports the artifact missing and `stub` reports a real
   detection.
2. **Four tasks depend on a module another task was supposed to create** (F7's cumulative
   workspace). `py_server_main`'s four dependencies appear nowhere in its verifier — its own
   dictated body imports them — so verifier-only dependency analysis misses them. Only the
   positive control caught it.
3. **`sec_xss_filter`'s prompt dictates un-runnable JavaScript.** The donor writes `[\s\S]` in a
   template literal, and JS evaluates that to `[sS]`; the dictated regex becomes a syntax error.
   Verified by running node, not by reading the spec. Left unrepaired — the 7 recorded runs used
   the corrupted prompt. Three other tasks are affected non-fatally.
4. **`python3` on the import host is the Microsoft Store alias shim** — on PATH, found by
   `command -v`, prints an advert and exits 9009. And `bash` on PATH is the WSL launcher. Both
   are why SPEC §8 says probe by *executing*, and why `gate.rs` does.
5. **Relative imports cannot survive the flatten.** `from .router import` needs a package; the
   flat work dir is not one.

## Design notes

- **The gate uses a null-implementation stub, not an absent artifact** (F19). Absence alone
  misses `fix_path_traversal`, whose import raises before reaching its swallowed `assert`.
- **Points 2 and 3 are measured, never tabled.** They run only for a task that already ships
  `refsol/` or `sham/` on disk, so `fix_sql_inject`'s quarantine is derived from running its
  authored sham — not from a hard-coded list. A from-scratch emit into an empty tree correctly
  reports 55/24/11, because that tree has no sham to run.
- **The gate3 30 is embedded, not re-derived** (`rewrite.rs::GATE3`). It is an approved decision
  (R9/R10); re-computing it from the results TSV is a way for it to drift silently.
- **`--force` overwrites generated output but never an authored task.** Generated files say
  `# GENERATED by` on line 1, which makes "was this authored" a fact rather than a judgement.

## Known gaps

- Every gate result here was measured on the **Windows host**, not in `abcc-agents`. A Linux
  re-run is the cheap unspent confirmation; the `absent`/`stub` error-class transition is the
  thing to check if it disagrees.
- Points 2 and 3 are `not_run` for 89 of the 90 tasks. That is step 4's work — but note that the
  positive control already establishes point 2 mechanically for 49 tasks, so emitting those
  dictated bodies as `refsol/` would close point 2 for them without authoring anything.
